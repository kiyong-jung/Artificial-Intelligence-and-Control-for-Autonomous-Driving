# 신경망 혼자 한 바퀴: 적색 통과 줄이기

규칙 없이 신경망만 운전해 최종 seed 180회 중 176회를 완주했다(학습 seed 3개 × 60회). 적색 통과 3회, 차 충돌 1회,
순간이동 0회, 정차는 4곳 중 3.93~3.95곳이다. 조건은 수업 기준 그대로다: 안전장치 끔, 관측 43개, 차로 지시 없음.

## 바꾼 것

| 무엇 | 어디 | 왜 |
|---|---|---|
| 규칙 운전사 v6(정답용) | `env/route_policy.py` `ExpertPolicyV6` | v5는 적색에 선 뒤 정지선 2m 앞까지 다시 다가가서, 따라 배운 신경망이 다가가다 넘었다 |
| 칸 고르기 출력 | `algorithms/bc.py`, `train_bc.py --loss bins` | 숫자 하나를 맞히면 "세게 줄인다"와 "그대로 간다"의 중간값을 낸다 |
| 신호만 바꾼 관측 더하기 | `research/av_bc_rl/augment_signals.py` | 정지선 15~25m 앞에서 황색을 만나는 순간이 데이터에 거의 없다 |
| DAgger 옵션 | `research/av_bc_rl/dagger.py` | 정답 다시 붙이기, 학습 인자 넘기기, 신호 바꾼 관측 더하기 |

v6이 v5와 다른 점은 신호 앞과 빈 도로의 속도뿐이다. 차로 고르기와 정류장은 v5 그대로다.

- 정지점을 정지선 4m 앞으로 당겼다. 그 앞 8m 안에서는 적색에 가속하지 않고, 서면 최대 제동으로 그대로 선다.
- 서는 감속은 정지점까지 필요한 값(v²/2d)이다. 1m/s²가 되면 줄이기 시작해 최대 감속 2m/s²까지 여유가 있다.
- 황색에 서기로 했으면 가속하지 않고, 지나가기로 했으면 가속도 변화 제한 없이 바로 가속한다.
- 신호에 다가가는 속도 상한과 황색 판단에 같은 여유(1m)를 쓴다. 상한을 넘으면 넘은 만큼 바로 줄인다.
- 앞이 비어 보여도 보이는 거리 50m 끝에 설 수 있는 속도(12m/s)를 넘지 않는다.

v6 혼자 달린 결과는 dev 30회와 train 30회 모두 완주, 충돌 0, 적색 통과 0, 정차 4.00이다
(`metrics/t3_expert_v6c_dev.json`, `metrics/t3_expert_v6c_train.json`). 최종 seed로는 재지 않았다. 바퀴 시간은 v5보다
10~30초 길다.

## 단계별 효과 (dev seed, 교통량마다 20회, 학습 seed 0)

"완주"는 60회 중 횟수다. 맨 위 두 줄은 앞선 측정(교통량마다 10회)이다.

| 단계 | 완주 | 적색 통과 | 충돌 | 정차 |
|---|---|---|---|---|
| v5 + 숫자 맞히기, DAgger 3회(앞선 측정) | 26/30 | 4 | 0 | 3.5 |
| v5 + 숫자 맞히기, DAgger 6회(앞선 측정) | 27/30 | 3 | 0 | 3.7 |
| 1. v6 + 숫자 맞히기, DAgger 1, 2, 3회 | 55, 59, 58 | 2, 1, 2 | 1, 0, 0 | 3.75, 3.95, 3.83 |
| 2. v6 + 칸 고르기, DAgger 1~4회 | 52, 57, 55, 57 | 4, 1, 3, 3 | 4, 2, 2, 0 | 3.55, 3.73, 3.90, 3.87 |
| 같은 합본 136만 줄에서 숫자 맞히기 | 57 | 3 | 0 | 3.83 |
| 같은 합본에서 칸 고르기 | 59 | 1 | 0 | 3.95 |
| 같은 합본에서 칸 고르기, 긴 정지 솎기(처음과 끝 2초만) | 54 | 5 | 0 | 3.78 |
| 같은 합본 + 신호만 바꾼 관측 30만 줄, 칸 고르기 | 60 | 0 | 0 | 4.00 |

- 1~2번 줄은 v6의 첫 판(황색 빈틈과 시야 속도 상한을 고치기 전)으로 잰 것이다. 합본 줄부터는 지금 v6이다.
- 합본은 시범 355바퀴와 위 실행들의 롤아웃 1,140바퀴에 지금 v6의 정답을 다시 붙인 것이다. 손실만 다르고 데이터가 같다.
- 칸 고르기는 정답을 더 잘 맞힌다. 합본에서 가감속 오차 평균이 0.039에서 0.021로, 최대 제동 정답에서는 0.045에서
  0.007로 줄었다. 주행 결과 차이(57회와 59회)는 60회로는 우연과 구분되지 않는다.
- 가감속 고르는 방법 셋. DAgger 전에는 차이가 컸다(양옆 칸 평균 18회, 전체 평균 12회, 가장 높은 칸 0회 완주).
  DAgger 5회 뒤에는 셋 다 60회 완주였다. 양옆 칸 평균(`--decode local`)을 쓴다.
- 긴 정지 솎기는 나빠졌다(적색 통과 1회에서 5회). 쓰지 않는다.
- 신경망이 제 가속도를 못 보게 하면(`--blind ego_acceleration`) DAgger 없이도 46회를 완주했다(보면 18회). 정답이 앞
  판단의 가속도와 비슷해서, 보면 제 앞 행동을 베낀다. DAgger 뒤에는 보는 쪽이 같거나 나았다(합본 59회와 58회,
  신호 바꾼 관측을 더하면 60회와 57회). 최종 구성은 본다.
- 모방학습만 한 모델은 제 가속도를 보는 구성이면 못 쓴다(60회 중 2~28회 완주). 정답이 -1인 "서 있기"를 엉뚱한 곳에서 내고 못 빠져나온다.
  DAgger가 그 자리의 정답(출발)을 더해 고친다.

- 목표(완주 95% 이상, 충돌 5% 미만, 적색 통과 2% 이하, 정차 3.9 이상, 순간이동 0)를 세 seed 모두 넘는다. 적색 통과는
  seed마다 60회 중 1회(1.7%)로 한도에 가깝다.
- 남은 적색 통과 셋 중 둘이 R111b다. 좌회전 직전 27m 도로로, 회전 속도에 맞춰 줄이며 다가가다 황색을 만나는 곳이다.
- 바퀴 시간은 468~515초, jerk 한계를 넘은 판단은 1.1~1.4%, 3m/s²를 넘는 급제동은 0이다.

## 다시 만드는 명령

```bash
export SUMO_HOME=...   # SUMO 1.27.1
D=data/research
# 1. 시범 데이터(v5로 모은 355바퀴)의 정답을 v6으로 다시 붙이고, 신호만 바꾼 관측을 더한다
python research/av_bc_rl/dagger.py --data $D/v4/demo_clean.npz --relabel-to $D/v6/demo_v6.npz --expert-version 6
python research/av_bc_rl/augment_signals.py --data $D/v6/demo_v6.npz --out $D/v6/demo_v6_aug.npz
# 2. 학습 seed마다(0, 1, 2): 모방학습, DAgger 5회, 평가
S=0
python train_bc.py --data $D/v6/demo_v6_aug.npz --seed $S --device cpu --epochs 40 --batch-size 512 \
    --loss bins --decode local --out-dir results/f_bc_s$S
python research/av_bc_rl/dagger.py --data $D/v6/demo_v6.npz --model results/f_bc_s$S/model.pt --iterations 5 \
    --episodes 30 --seed $S --out results/f_dagger_s$S --augment-signals --epochs 40 --batch-size 512 \
    --loss bins --decode local
python research/av_bc_rl/evaluate.py --policy bc --model results/f_dagger_s$S/bc_it5/model.pt --split final \
    --episodes 20 --label f_dagger_s${S}_it5
python research/av_bc_rl/summarize_runs.py --places research/av_bc_rl/metrics/f_dagger_s*_it5_final.json
```

5회 모델은 `research/av_bc_rl/models/v6_bins_dagger_s{0,1,2}/`에 있다(`model.pt`, `run_config.json`, `config.json`).
저장소의 모델로 바로 재려면 `--model research/av_bc_rl/models/v6_bins_dagger_s0/model.pt`를 준다.

## PPO로 넘어가기 전에

- 시작점으로 쓸 수 있다. 세 seed 모두 최종 seed에서 97% 넘게 완주한다.
- 출력이 칸 점수라 지금 `algorithms/ppo.py`(가감속 평균과 표준편차)와 모양이 다르다. 가감속을 범주형 분포로 받는
  정책이 필요하다. 아직 만들지 않았다.
- 남은 실패가 드물다(60회에 1~2회). 보상으로 고쳐졌는지 보려면 평가 횟수를 늘려야 한다.
