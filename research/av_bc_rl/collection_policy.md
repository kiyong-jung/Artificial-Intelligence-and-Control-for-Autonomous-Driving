# 데이터 수집 정책 (`--policy expert-v5`)

BC 데이터를 모으는 규칙 정책이 무엇을 쓰고 무엇을 쓰지 않는지 적는다. 조교님께 규칙 기반 시연 데이터가 허용되는지
물을 때 이 문서를 근거로 쓴다. 코드는 `env/route_policy.py`의 `ExpertPolicyV5`다.

## 환경이 버스를 돕지 않는다

수업 원본(`upstream/main:env/sumo_env.py`)과 같은 설정이다. 값은 `env/road_config.py`의 `_EGO_COMMON`에 있다.

| 항목 | 값 | 뜻 |
|---|---|---|
| `speed_mode` | 0 | SUMO가 앞차, 교차로 우선권, 적색 신호 앞에서 버스를 세우지 않는다 |
| `lane_change_mode` | 0 | SUMO가 스스로 차로를 바꾸지 않고, 요청은 옆 차 간격과 무관하게 실행한다 |
| 속도 상한 | 경로 최고 속도(13.89m/s) | 차로 제한속도와 곡선 제한은 관측에만 있다. 환경은 그 속도로 자르지 않는다 |
| 차선변경 게이트 | 수업 원본 그대로 | 앞 3m + 0.15v, 뒤 3m + 0.3v. 차로 끝 예외는 없앴다 |

환경이 하는 일은 넷이다.

- 가속도를 판단 한 번(0.5초) 동안 명령값까지 곧게 바꾼다(구동계).
- 차선변경이 끝나면 차로 가운데로 옮긴다(조향). `lane_change_mode` 0에서 SUMO는 차체가 목표 차로에 다 들어간 곳
  (가운데 0.35m 앞)에서 변경을 끝낸다. 가운데 맞춤 비트(1024)는 SUMO가 옆 차와 옆 간격을 지키는 움직임도 함께 켜므로
  쓰지 않았다(`env/sumo_env.py`의 `_steer`).
- 차선변경이 차로 경계를 넘는 동안(약 1.6초) 간격 게이트를 계속 보고, 깨지면 제 차로 가운데로 되돌린다. 수업 원본의
  차선변경은 한 계산에 끝나 게이트를 명령 때 한 번만 본다. 여기서는 넘어가는 사이 옆 차로에 차가 들어올 수 있다.
  되돌린 스텝은 기록의 `action.lane_change_aborted`에 남는다.
- 충돌(차, 보행자)과 적색 정지선 통과를 찾아 에피소드를 끝낸다. 기록의 `event.collided`,
  `event.pedestrian_collision`, `event.red_light_violation`, `event.termination_reason`에 남는다.

## 정책이 쓰는 것

정책 입력은 43차원 관측(`env/data_schema.py`의 `OBSERVATION_FEATURES`)뿐이다. 같은 관측이면 같은 행동을 낸다.
내부 상태와 난수가 없다.

| 관측 | 쓰는 곳 |
|---|---|
| 내 속도, 내 가속도 | 모든 가감속 판단, 가속도 변화 제한(승차감) |
| 현재 차로 앞차의 간격과 상대 속도 | 추종(IDM)과, 앞차가 급정지해도 설 수 있는 속도 유지(추돌 회피) |
| 옆 차로 앞뒤 차의 간격과 상대 속도 | 차선변경 틈 판단 |
| 차로별 연결성(5개) | 차로 고르기. 지금 차로가 경로에서 끊기면 더 멀리 이어지는 쪽으로 옮긴다 |
| 신호 거리, 적색, 황색, 비보호 녹색 | 적색 정지선 앞 정지, 황색 판단, 신호에 다가가는 속도, 비보호 녹색 앞 감속 |
| 다음 정류장 거리, 남은 정차 시간 | 정류장 정차 |
| 횡단보도 거리, 사람이 있는지 | 횡단보도 앞 정지 |
| 지금 자리의 제한속도, 앞쪽 가장 낮은 제한속도와 거리 | 목표 속도, 회전 전 감속 |

생성자가 받는 고정 값은 버스 제원(최대 가감속), 관측 정규화 거리, 환경 게이트 값이다. 운전 파라미터(반응 시간
1.5초, 편안한 감속 1.5m/s², 황색이 3초는 이어진다는 가정 등)는 클래스 상수다.

차로를 고르는 근거는 둘이다.

1. **차로별 연결성.** 수업 원본 관측의 `[21..25]`와 같은 값이다. 차로마다 경로를 따라 이어지는 거리다.
2. **정류장은 길가에 있다는 상식.** 정류장이 200m 안에 있고 오른쪽에 정류장까지 이어지는 차로가 있으면 오른쪽으로 간다.

## 정책이 쓰지 않는 것

- SUMO 내부 상태(`state`), 도로 id, 차로 번호, 좌표, 경로 거리. 정책 코드에 도로 이름과 위치가 없다.
- 어느 차로로 가라는 값. 스키마 v3의 `route_lane_offset`, `route_lane_continuation`, `stop_lane_offset`은 관측에서 뺐다.
- 지난 관측과 시각. 판단마다 지금 관측 하나만 본다.
- 교차 방향 차량. 관측에 없다. 비보호 녹색 앞에서는 속도만 줄인다.

## 정답용 정책 v6 (`--policy expert-v6`)

신경망에 붙일 정답은 `ExpertPolicyV6`가 낸다. 쓰는 관측과 쓰지 않는 것은 v5와 같고 내부 상태도 없다. 다른 점은 신호 앞에서
서는 방법과 빈 도로의 속도 상한뿐이다(적색에 선 뒤 다가가지 않음, 정지점 4m 앞, 황색 판단 여유, 보이는 거리 끝에 설 수 있는
속도). 이유와 측정은 `research/av_bc_rl/bc_redlight.md`에 있다. 시범 관측은 v5로 모은 것을 그대로 쓰고 정답만 v6으로 다시
붙였다.

## 조교님께 확인할 것

1. **규칙 기반 시연 데이터.** 이 정책은 학습한 모델이 아니라 사람이 쓴 규칙이다. 자율주행 차량(학습할 모델)을 돕는
   규칙이 아니라 BC 데이터를 만드는 운전자 역할이다. 이 용도가 "규칙 기반으로 자율주행 차량에 도움을 주면 안 된다"에
   걸리는지 확인한다.
2. **연결성을 보는 거리 200m.** 수업 원본은 관측 거리 W(50m)까지 본다. 합정역은 좌회전 직전 도로(R111b)가 27m라,
   50m로는 끝나는 차로를 그 도로에 들어선 뒤에야 안다. `OBSERVATION["connectivity_range"]`를 200m로 두었다. 값의
   뜻은 원본과 같지만(차로마다 이어지는 거리), 멀리 볼수록 "어느 차로로 가라"에 가까워진다. 50m로 되돌린 결과는
   아래 표에 있다.
3. **경로 기준 연결성.** 원본은 다음 도로로 이어지지 않는 차로를 끊긴 차로로 본다. 우리는 버스 경로의 다음 도로로
   이어지지 않는 차로(좌회전 교차로의 직진 전용 차로)도 끊긴 차로로 본다. 지도 수준의 경로 정보로 볼 수 있는지 확인한다.
4. **횡단보도와 신호 관측 거리 100m.** 버스 감속 한계(2m/s²)로 50km/h에서 서려면 약 60m가 필요하다.
5. **적색 통과와 보행자 충돌에서 에피소드 종료.** 수업 원본에는 신호와 보행자가 없다. 충돌과 같은 종료로 두었다.
6. **차선변경 중 게이트.** 원본의 게이트를 차로 경계를 넘는 동안에도 본다. 원본에 있는 규칙을 길어진 차선변경에
   맞춘 것이지만 환경이 차선변경을 되돌리는 것이므로 확인한다. 240회에서 1번 되돌렸다.

## 측정

코드는 커밋 `ddef532`다. dev(1000번대)와 train(2000번대) seed로 고치고, final(9000번대)은 마지막에 한 번 돌렸다.
교통량마다 seed가 다르다(quiet +0, baseline +300, busy +600). 다시 재는 명령은
`python research/av_bc_rl/evaluate.py --policy expert-v5 --split final --episodes 20 --label compliant_v5`다.

final seed, 교통량마다 20회(`metrics/compliant_v5_final.json`)

| 교통량 | 완주 | 차 충돌 | 보행자 충돌 | 적색 통과 | stuck | 순간이동 | 정차(4곳 중) | 급제동(3m/s² 초과) | 최대 감속 | 횡가속도 최댓값 | 바퀴 시간 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| quiet | 20/20 | 0 | 0 | 0 | 0 | 0 | 4.00 | 0 | 2.00m/s² | 2.03m/s² | 426 ± 36초 |
| baseline | 20/20 | 0 | 0 | 0 | 0 | 0 | 4.00 | 0 | 2.00m/s² | 2.03m/s² | 436 ± 41초 |
| busy | 20/20 | 0 | 0 | 0 | 0 | 0 | 4.00 | 0 | 2.00m/s² | 2.03m/s² | 435 ± 30초 |
| 합계 | 60/60 | 0 | 0 | 0 | 0 | 0 | 240/240 | | | | |

- dev 90회와 train 90회도 모두 완주했고 충돌과 적색 통과가 없다(`metrics/compliant_v5_dev.json`,
  `metrics/compliant_v5_train.json`). 세 집합을 합쳐 240회다. 실패가 0번이어도 실패율이 0이라는 뜻은 아니다. 240회에서
  0번이면 실패율의 95% 상한은 약 1.2%다.
- SUMO가 요청 속도를 바꾼 스텝은 0이다. 환경이 차선변경을 되돌린 것은 240회에서 1번이다(train baseline 2300).
- 바퀴 시간은 안전 보조를 켠 때보다 25~36초 길다(dev 404, 402, 411초에서 440, 431, 436초). 신호에 30km/h 안팎으로
  다가가기 때문이다. 버스
  감속 한계(2m/s²)와 황색 3초로는 50km/h에서 정지선 35~57m 앞이 서지도 지나가지도 못하는 구간이다.
- jerk 한계(2m/s³)를 넘은 스텝은 0.8~0.9%다. 버스의 가감속 한계가 행동 한계라 3m/s²를 넘는 감속은 나올 수 없다.
- 교차로 안에 선 것(도로망 3.20.0, `metrics/map320_check_v5_dev.json`, `metrics/map320_check_v5_final.json`).
  버스가 교차로 안 차로에 30초 넘게 선 것은 final 60회에서 9번, dev 60회에서 5번이고 모두 J2(`:J2_1`)다. J2는 양화로
  R54의 맨 오른쪽 차로가 우회전 연결로 R65로 갈라지는 곳이다. SUMO가 교차로로 만들었지만 겹치는 연결(foes)이 하나도
  없고 횡단보도도 없다. 합정역 사거리(J1) 신호 대기 줄이 R42(16m)를 넘어 이어진 것이고, 버스가 R54 끝에 서 있을 때와
  막는 차가 같다. SUMO 배경 차도 같은 자리에 36.5초까지 선다. SUMO는 겹치는 연결이 있을 때만 교차로를 비운다
  (`MSVehicle::keepClear`). 그래서 정책은 고치지 않았다. 겹치는 연결이 있는 교차로 안에 10초 넘게 선 것은 두 집합
  모두 0번이다. `behavior_metrics.py`의 `junction_stops_by_place`가 둘을 나눠 센다(`10s`, `30s`는 막는 곳,
  `free_10s`, `free_30s`는 막지 않는 곳).

고치기 전 train 90회에서 나온 실패 셋과 원인이다.

데이터 검사(`python research/av_bc_rl/check_dataset.py <jsonl.gz>`)

- final 기록 3개, 51,878행: 컬럼 표의 모든 컬럼과 안쪽 키가 있고, NaN과 무한대가 없고, 관측과 행동이 [-1, 1] 안이고,
  JSONL과 NPZ가 같다. 오류 0개.
- 결정성: train busy seed 2600의 12회를 두 번 모았다. 10,345행이 모두 같다(`--same-as`).

  12개로 늘려도 1.2배뿐인 것은 워커마다 프로세스가 둘(파이썬, SUMO)이라 코어가 모자라기 때문이다.
