# 주변 교통(Traffic)

자율주행버스 주변의 다른 차량과 보행자가 버스를 마주했을 때 어떻게 반응하는지를 SUMO에서 구현하고, 설정한 대로 나오는지 숫자로 확인한다. 버스 자체의 주행 정책은 범위 밖이다. 버스는 외부에서 들어오는 차량으로 취급하고 `bus_hook(traci, t)`로만 붙는다.

검증 수치와 한계 전부는 [VERIFICATION.md](VERIFICATION.md)에 있다. 이 문서는 구조, 사용법, 이슈를 적는다.

### 주행 모델과 양보 성격

배경 차량의 주행 모델은 `env/road_config.py`가 정한다(Krauss 35%, IDM 30%, EIDM 20%, ACC 15%). 양보 성격은 그 위에 독립으로 붙는다.

- `YieldManager(type_mix={"yielder": .5, "nonyielder": .5}, mix_vtype_prefixes=("car_",))`를 주면, 이름이 `car_`로 시작하는 차량이 투입될 때 성격을 뽑아 받는다. 주행 모델은 바뀌지 않는다.
- 차량마다 `driver.type`, `driver.pYield`, `driver.delay`, `driver.newTau`가 차량 파라미터로 기록된다.
- 인자를 주지 않으면 vType 이름이 `yielder`, `nonyielder`로 시작하는 시험 차량만 대상이다.
- 양보형도 SUMO 내장 협조 차선 변경을 끈다(`lcCooperative=-1`, `lcCooperativeSpeed=0`). 켜 두면 양보 판정과 무관하게 SUMO가 길을 비켜서 양보율이 100%가 된다.
- `type_mix`를 켜면 `car_*` 차량 전체에 위 설정이 적용되어, 투입 이후 배경 차량의 차로 변경이 SUMO 기본과 달라진다.

### 합정역 연결 (`hapjeong.py`)

`HapjeongTraffic`은 도로를 공식 경로로만 만든다. `maps/hapjeong`을 `configure_map`이 읽고, `road_builder.build`가 실행 폴더를 만든다. `maps/`와 도로망 파일은 건드리지 않는다. 실행 폴더에 다음을 더한다.

| 이름 | 내용 |
|---|---|
| A1 | 배경 차량 `car_*`에 양보 성격을 투입 시 붙인다 |
| S5 | 독막로에 합류하는 골목 `G3`, `G12`에서 나오는 흐름 14개를 끼어들기형 vType으로 바꾼다 |
| S6 | 와우산로 횡단보도를 건너는 보행자 50명을 P1/P2로 나눈다 |
| S4 | 선택. `taxi_depart`를 주면 `R69` 안쪽 차로 정류장 앞에 택시가 선다 |

`start()`가 배경 교통을 180초 흘리고, `run()`이 공통 실행 루프를 돌린다. 버스는 만들지 않는다. 버스 제어 쪽이 `bus_hook`으로 넣고 몬다.

## 실행

```bash
python scripts/run_hapjeong_scenario.py                         # sumo-gui가 열리고 버스를 따라간다
python scripts/run_hapjeong_scenario.py --nogui --seconds 900   # 화면 없이 요약만
pytest tests                                                    # 25개, 약 40초
```

시나리오 화면에서 보이는 것:

- 빨간 버스가 정류장 6곳에 8초씩 서며 `bus_loop`를 돈다(한 바퀴 약 417초). 차로 변경이 필요하면 방향지시등을 3초 켠 뒤 요청한다. 주행 정책이 아니라 규칙이다.
- 주변 차량 색은 주행 모델이다. 노랑 Krauss, 청록 IDM, 주황 EIDM, 자홍 ACC, 회색 끼어들기 차량.
- 버스가 차로 변경 의사를 보이면 뒤차에 고리가 생긴다. 초록은 이번 상호작용에서 양보, 빨강은 비양보로 판정한 것이다. 고리는 끝난 뒤 4초 더 남는다. 같은 내용을 터미널에도 한 줄씩 적는다.
- 차량은 양보형(양보 확률이 높음) 또는 비양보형(낮음) 성격을 갖고, 판정은 그 확률로 상호작용마다 한 번 뽑는다. 그래서 양보형도 비양보로 판정될 수 있고, 같은 차량이 여러 번 마주치면 판정이 바뀔 수 있다.
- 차량을 더블클릭하면 파라미터에서 `driver.type`, `driver.pYield`를 볼 수 있다.

교통이 한산해 상호작용이 드물어서 두 가지 장치를 넣었다. 둘 다 확인용이고 실제 교통이 아니다.

- 시험 차로 변경(`--probe`, 기본 10초): 옮겨 갈 차로 뒤 40m 안에 차가 있으면 일부러 그쪽으로 차로를 바꾼다. 0이면 끈다.
- 동행 차량(`comp1`처럼 표시): 뒤에 차가 없으면 30m 뒤에 배경 차량 한 대를 넣는다. `--no-companion`으로 끈다.

그 밖의 옵션: `--seed`, `--scenario quiet|baseline|busy`, `--delay`(클수록 느림), `--zoom`, `--no-track`, `--no-stops`, `--no-overtake`, `--seconds`.

알고리즘별 상세 검증은 `scripts/verify_a1.py`, `verify_a2.py`, `verify_a3.py`, `verify_hapjeong.py`이고 결과는 `results/traffic_verification/`에 쓴다.

## 검증 결과

| 확인한 것 | 결과 |
|---|---|
| A1 양보율, 합정역 독막로 4차로 배경 교통 속, 유형별 200회 | 양보형 0.785(설정 0.82), 비양보형 0.155(설정 0.17). 허용 ±0.05 안 |
| A1 양보 결정과 실제 결과 | 100% 일치. 양보 확률 0에서 SUMO가 스스로 비켜주는 비율(누출)은 0% |

| 모델과 성격을 독립 조합, 합성 도로, 모델별 400회 | 양보형 설정 0.833에 실측 0.852, 비양보형 설정 0.170에 실측 0.157. 결정과 결과 100% 일치 |
| 합정역 배경 교통에 A1+S5+S6를 켜고 seed 2개 × 300초 | 충돌 0, 순간이동 0 |

한계: 모델별 감속 크기의 차이는 통계 검정을 하지 않았다. 독립 조합은 합정역 전체가 아니라 합성 도로의 후행차 한 대로 확인했다. 합정역에서는 모델당 1회씩 돌아가는 것만 확인했다.

## 이슈와 한계

**아직 이어지지 않은 것**

- `traffic/`은 학습 환경 `SumoHighwayEnv`에 연결되어 있지 않다. 학습은 팔달문에서만 돌고, 합정역은 0번 차로가 인도라 차로 번호 관측이 틀려 막혀 있다. 합정역 주변 교통은 시나리오 스크립트와 검증 스크립트에서만 돈다.
- 버스 정책 코드가 없다. `bus_hook`과 시험용 규칙 버스로만 확인했다. 버스 쪽이 지킬 것은 두 가지다.
  - 차로 변경 전에 방향지시등을 켠다. A1의 진입 의사 판정 조건이다(방향지시등, 출구 거리, 직전 2초 전진).
  - `laneChangeMode`를 1109나 0으로 쓰지 않는다. 뒤차가 양보하든 말든 버스가 밀고 들어가 양보 검증이 성립하지 않는다. 1621, 512는 정상이다.

**시나리오 발생이 보장되지 않는다**

- 합정역 교통이 한산해서 자연 교통에서는 버스가 뒤차와 상호작용하는 일이 한 바퀴에 한두 번이다.
- S5(골목 흐름이 시간당 약 23대)와 S6는 시나리오 스크립트에서 발생을 확인하지 못했다. S4는 코드만 있고 스크립트에서 켜지 않는다.
- S1(정류장 출발 후 재합류)은 구현하지 않았다. 정류장이 배이형인지 차로 정차형인지 로드뷰로 확정해야 한다.
- S2(정류장 직후 좌회전 연속 차로 변경)는 시나리오에서 필요한 차로 변경이 있었는지 확인하지 못했다.

**도로**

- 도로망이 3.4.0이 됐다. 골목은 모두 나오는 방향의 일방통행이고, 독막로 남쪽 골목망과 `G1`·`G2`·`G5`~`G7`·`G9`~`G11`·`G13`~`G15`는 없어졌다. `G16`으로 나오는 차는 `G4`에서, `G18`로 나오는 차는 `G17`에서 출발한다. 독막로 `R111b`는 차도 3차로다(2번·3번 차로가 좌회전). 신호는 `J82`, `J42`, `J106`, `J48`이 바뀌었다([maps/hapjeong/README.md](../maps/hapjeong/README.md)의 3.4.0 절). 골목이 버스 경로로 나오는 도로는 `G3`·`G12`(독막로), `G24`(와우산로, 극동방송 앞), `G19`(잔다리로 `J74`), `G16`·`G23`·`G18`(잔다리로), `G22`(잔다리로 `J48`, 좌회전 대기 구간 앞)다. `cutin.py`의 대상은 지금 `G3`, `G12`뿐이다. 배경 차량은 무작위 간격으로 들어온다(`flow_arrivals`).
- 도로망이 3.2.0으로 바뀌었다(북서쪽을 잘라내고 잔다리로로 나오는 지름길 두 개를 더함, [maps/hapjeong/README.md](../maps/hapjeong/README.md)). 위 검증 수치는 2.0.0 도로 기준이므로 다시 돌려야 한다. 3.2.0에서는 `pytest tests` 통과만 확인했다. `R43`은 맨 왼쪽 차로가 버스 전용이다. 잔다리로 `-R96`은 합류점 두 곳에서 나뉘어 `-R96`, `-R96.64`, `-R96.201`이 됐다. 신호 없는 횡단보도에는 보행자 `s6ped*`가 시간당 60명 건넌다.
- 이 코드가 기대는 도로 ID. 바꾸면 알려야 한다.
  - 골목 `G3`, `G12`와 합류점 `X_dongmak3`, `X_dongmak6`
  - 횡단보도 `S6_wausanro`와 와우산로 `R112`, `-R112`
  - 4차로 구간 `R43`, `R71`, `R71.135`
  - 택시용 `R69`와 주차 차로 `R69_1`
  - `bus_loop` 경로와 정류장 6곳
- S6 횡단보도는 보행자 유형이 의미를 갖도록 비우선으로 바꿨다. 한국 법규(운전자 일시정지 의무)와 다르다.

**값**

- 양보 확률, 반응 지연 분포, 끼어들기 분포(`default_bins`)는 임의의 초깃값이다. 끼어들기는 설정 확률이 곧 진입 확률이 아니어서(설정 0.05에서 실측 0.13) 구간별 보정이 필요하다.
- 승객 가중 지연의 탑승 인원(승용 1.3, 택시 1.5, 버스 20)은 근거 없는 가정값이다.
- 배경 차량의 추종 모델 파라미터도 현장 실측값이 아니다.
