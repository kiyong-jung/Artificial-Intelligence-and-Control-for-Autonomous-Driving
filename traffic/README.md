# 주변 교통(Traffic)

자율주행버스 주변의 다른 차량과 보행자를 SUMO 수요와 운전자 모델로 움직이고, 버스가 마주치는 시나리오(S1~S6)가 얼마나 자연스럽게 생기는지 숫자로 잰다. 배경 차와 보행자를 버스 위치에 맞춰 넣거나, 지우거나, 속도·차로를 지정하지 않는다. 버스 자체의 주행 정책은 범위 밖이다. 버스는 외부에서 들어오는 차량으로 취급하고 `bus_hook(traci, t)`로만 붙는다.

자연 교통에서 잰 시나리오 발생률은 아래 [측정 결과](#측정-결과-자연-교통)에 있다. 예전 조종 방식(A1 양보율 등)의 검증 수치는 [VERIFICATION.md](VERIFICATION.md)에 남아 있다. 이 문서는 구조, 사용법, 이슈를 적는다.

### 주행 모델과 운전자 성향

배경 차량의 주행 모델은 `env/road_config.py`가 정한다(Krauss 35%, IDM 30%, EIDM 20%, ACC 15%). 운전자 성향은 그 위에 독립으로 붙는다.

- 이름이 `car_` 또는 `cutin_`으로 시작하는 차량이 투입될 때 `YieldManager.on_departed`가 운전자 성향 a ~ Beta(2, 2)를 하나 뽑는다(`draw_driver`).
- 파라미터마다 a에 N(0, 0.15) 흔들림을 더해 [0, 1]로 자른 값을 선형으로 옮긴다. 공격적일수록 덜 협조하고, 속도 이득 차선 변경을 더 하고, 좁은 간격도 받아들이고, 조금 빨리 달린다.
  - `lcCooperative`(= `lcCooperativeSpeed`) 1.0~0.2, `lcSpeedGain` 0.5~2.0, `lcAssertive` 0.8~1.6, `lcImpatience` -0.5~0.5(SL2015만)
  - `speedFactor` 0.92~1.08에 N(0, 0.05)를 더하고 0.8~1.2로 자른다
- 차량 파라미터 `driver.aggressiveness`에 a를 남긴다. A1·S1 관찰 기록에도 들어간다.
- 예전의 양보형·비양보형 두 집단, 모든 차의 협조 차선 변경을 끄던 `lcCooperative=-1`, 공격성 값→확률 변환은 지웠다.

### 합정역 연결 (`hapjeong.py`)

`HapjeongTraffic`은 도로를 공식 경로로만 만든다. `maps/hapjeong`을 `configure_map`이 읽고, `road_builder.build`가 실행 폴더를 만든다. `maps/`와 도로망 파일은 건드리지 않는다. 실행 폴더에 다음을 더한다.

| 이름 | 내용 |
|---|---|
| A1 | 배경 차량 `car_*`·`cutin_*`에 운전자 성향을 투입 시 붙이고, 버스의 차선 변경 때 목표 차로 후행차를 관찰한다 |
| S1 | `run(stop_bypass=True)`(기본). 버스가 정류장에 서면 바로 뒤 차량이 기다렸는지 추월했는지 기록한다 |
| S5 | 도로망의 신호 없는 골목 출구 11곳(골목 6개가 큰길 양쪽 방향으로 나가는 곳)으로 나오는 흐름을 모두 골목 운전자 분포(`cutin`)로 바꾼다(busy 기준 흐름 72개). 골목은 도로 종류로 정하고 버스 경로를 보지 않는다. 신호 교차로(`J74`, `J48`, `cluster_J52_J56_J58`)는 신호가 순서를 정하므로 뺀다. 연결로 `R65`~`R67`(primary_link, 등급 7)은 제한속도가 30 km/h여도 골목이 아니다. S5 측정은 이와 따로, 버스 경로(`bus_loop`)에 합류하는 골목 6곳(`X_dongmak3`, `X_dongmak6`, `X_wausan11`, `X_jandari7`, `X_jandari2`, `X_jandari3`)에서 나온 차를 센다. 예전에는 버스 경로로 합류하는 흐름(36개)만 바꿨다 |
| S6 | 모든 보행자에게 보행자 분포(`pedDist`)를 준다(`ped_types=True`, 기본) |
| S4 | `bus_traffic`을 주면 정류장 근처 택시 정차가 함께 들어간다(`BusTrafficCfg.curb_taxis_per_h`). 그 밖에 `HapjeongTraffic(stopped=[StoppedSpec(...)])` 또는 `taxi_depart`(예전 방식)로 정한 정차 차량을 넣는다. 스크립트에서는 `--stopped`로 켠다 |

`start()`가 배경 교통을 180초 흘리고, `run()`이 공통 실행 루프를 돌린다. 버스는 만들지 않는다. 버스 제어 쪽이 `bus_hook`으로 넣고 몬다. `run(triggers="scenario")`는 A1이 버스의 의사를 읽는 구간을 S2(좌회전 직전), S3(정류장 접근), S4(정차 차량 앞)로 한정한다. 기본(`None`)은 방향지시등만 본다.

## 실행

```bash
python scripts/run_hapjeong_scenario.py                         # sumo-gui가 열리고 버스를 따라간다
python scripts/run_hapjeong_scenario.py --nogui --seconds 900   # 화면 없이 요약만
pytest tests                                                    # 113개, 1분 남짓
python scripts/verify_additional.py                             # 추가 행동 검증 전체(s4 s5 ped det hap). 인자로 골라서 돌린다
```

정차 차량(S4)을 스크립트에서 켜는 예. 쉼표로 이은 `key=value`이고 `--stopped`는 여러 번 줄 수 있다.

```bash
# 합정역7번출구 정류장 14m 앞에 택시, warmup 60초 뒤 투입, 40초 정차
python scripts/run_hapjeong_scenario.py --nogui --stopped kind=taxi,stop=합정역7번출구,depart=60,duration=40
# 도로·차로·위치를 직접: 버스 한 대, 발생 확률 0.5
python scripts/run_hapjeong_scenario.py --nogui --stopped kind=bus,edge=R112,lane=1,pos=60,depart=100,duration=40,prob=0.5
```

`kind`는 `taxi`, `bus`, `car`(일반 승용차)이다. `depart`는 warmup이 끝난 시점부터 센 초다. `--triggers scenario`, `--no-stop-bypass`도 있다.

시나리오 화면에서 보이는 것:

- 빨간 버스가 정류장 4곳(s2·s4·s5·s6)에 8초씩 서며 `bus_loop`를 돈다. 차로 변경이 필요하면 방향지시등을 3초 켠 뒤 요청한다. 주행 정책이 아니라 규칙이다.
- 주변 차량 색은 주행 모델이다. 노랑 Krauss, 청록 IDM, 주황 EIDM, 자홍 ACC, 회색 골목 운전자(`cutin`), 진노랑 택시.
- 버스가 차로 변경 의사를 보이면 목표 차로 뒤차에 흰 고리가 생긴다(관찰 중, 조종하지 않는다). 끝나면 초록은 버스가 먼저 들어감, 빨강은 뒤차가 먼저 지나감, 회색은 그 밖이다. 고리는 끝난 뒤 4초 더 남는다. 같은 내용을 터미널에도 한 줄씩 적는다.
- 차량을 더블클릭하면 파라미터에서 `driver.aggressiveness`(운전자 성향)와 `laneChangeModel.*`을 볼 수 있다.



그 밖의 옵션: `--seed`, `--scenario quiet|baseline|busy`, `--delay`(클수록 느림), `--zoom`, `--no-track`, `--seconds`, `--lane-buses`·`--taxis`(배경 버스·택시 대수). 시나리오 주입기와 그 옵션(`--no-inject`, `--no-stop-ahead`), 예전 `LoopBus`의 순항·선택적 추월·시험 차선 변경·동행차는 지웠다.

**시험용 버스(`traffic/test_bus.py`의 `TestBusPilot`)**: 노선은 R68 → 성산중학교(s2, 그 앞 S3) → J82 앞 좌회전 차로(S2) → 극동방송(s4) → 서교동교회(s5) → J42 좌회전 → 합정역(s6) → J1 앞 좌회전 차로(S2) → R68. 같은 창에서 차로를 여러 칸 옮기면(J1 앞) 이어지는 변경은 방향지시등 1초 뒤 바로 요청한다. 창 끝이 제동 거리 안인데 지금 차로가 목표 차로에 닿지 못하면 SUMO 기본 차선 변경(전략·협조, 1621)에 넘긴다(`handed`). SUMO가 차로 끝까지 빈틈을 찾고 이웃 차는 제 협조 성향만큼 자리를 내준다. 창 끝까지 못 가면 `missed`로 남긴다. 정류장 창(S3)이면 그 정류장을 이번 바퀴만 건너뛰고(달리는 차로에 서서 정류장 차로를 기다리지 않는다), 좌회전 창(S2)이면 SUMO에 맡긴 채 정지선에서 기다릴 수 있다. 창 끝 도로를 지나면 다시 512로 돌린다. 예전에는 창 끝 앞 달리는 차로에서 속도 0으로 멈춰 빈틈을 기다렸다(`forced`).

**측정**: `scripts/measure_s1_s6.py <수요> <seed> [꼬리표]`가 시험용 버스 3바퀴 동안 S1~S6 횟수(S2는 J82·J1 따로), 횡단보도 앞 차량 대기, 충돌·순간이동, 버스 반경 안 출현·소멸(`presence`), 신호 영역에서 시작한 A1 관찰 수, 바퀴별로 선 정류장, `missed`·`handed`·`slowed`, 버스가 정류장 밖에서 앞차도 적색도 없이 선 구간(`bus_still`: 길 가운데 `midblock`, 정지선·차로 끝 `stopline`, 교차로 안 `junction`)을 센다. S1~S6는 모두 위치로만 판정한다(누가 넣은 차인지 보지 않는다). 꼬리표: `hiped`(횡단보도 보행자 4배), `noror`(우회전 끔), `noped`(보행자 뺌), `nolr`(정지선 포기 끔). 결과의 `lane_route`는 진로를 바꾼 차 수, `wrong_lane_waits_at_end`는 끝난 시각에 잘못 든 차로의 정지선에 서 있던 차들의 대기 시간이다. 한 번에 4~10분 걸린다. `scripts/summarize_s1_s6.py <수요>`가 여러 시드를 바퀴당 비율(평균, 표준편차, 범위)로 모은다.

알고리즘별 상세 검증은 `scripts/verify_a2.py`, `verify_a3.py`, `verify_hapjeong.py`, `verify_additional.py`이고 결과는 `results/traffic_verification/`에 쓴다. 양보율을 설정대로 맞추던 A1 검증(`verify_a1.py`, `verify_a1_modes.py`)은 A1이 관찰만 하게 되어 지웠다.

  - 차로 변경 전에 방향지시등을 켠다. A1 관찰의 진입 의사 판정 조건이다(방향지시등, 출구 거리, 직전 2초 전진).

**우회전과 보행자**

- 우회전은 겹치는 직진·좌회전이 녹색이 아니고 횡단보도 보행자 신호가 적색일 때만 열려서, 원래 막힌 시간의 약 16~67%만 열린다(J74 67%, J42 39%, J96 41%, J82 43%, J83 19%, J52 군 16%). 런타임에 링크 상태를 바꾸는 보호 장치(`setLinkState`)는 합정역에서 교차로를 막아(순간이동 30건, 버스 R73 정지) 쓰지 않는다.
- J96의 우회전 링크(`-R127→R124`)에서 차량-보행자 충돌이 측정 중 간혹 나왔다. 그 링크는 원래 프로그램에서도 37% 동안 녹색(`g`)이라 우회전을 열기 전부터 있던 위험일 수 있으며 확인하지 못했다.

**시나리오 발생이 보장되지 않는다**

- 시나리오는 수요와 SUMO 운전자 모델에서 생긴다. 바퀴마다 일어난다는 보장은 없고, 바퀴당 비율은 측정값이다(위 측정 결과, `scripts/summarize_s1_s6.py`).
- 버스와 무관하게 남은 런타임 개입은 두 가지다. `right_turn.py`는 적색 중 우회전을 `g`로 연다(감사 지적, 이번에 바꾸지 않았다). `LaneRouteAdapter`(정지선 포기)는 운전자 행동이라 남겼다. 근거는 아래와 같다(busy seed 0~3, 3바퀴, 2026-11-23).
  - SUMO 차는 다음 도로로 가는 연결이 없는 차로에 있으면 정지선에 서서 옆 차로의 빈틈을 기다린다. 못 들어간 차는 SUMO가 `wrong lane` 순간이동으로 치웠는데, 순간이동을 끈 뒤로는 그대로 서서 그 차로를 막는다. SUMO의 경로 재탐색 장치(`device.rerouting`)는 교차로 가까이에서는 다음 도로를 바꾸지 않아(`MSVehicle::getRerouteOrigin`) 이 일을 대신하지 못한다.

B1은 `R114`에서 `R49a` 차로 1로 들어와 22.9 m 안에 버스 차로 4로 세 칸 옮겨야 하고(옮기는 데 10초 안팎), B4는 `R55` 버스 차로 5에서 102.7 m 안에 차로 1로 네 칸 옮겨 우회전해야 한다(seed 2에서 정지선 35 m 앞에서부터 끝날 때까지 320초 넘게 `R55`를 떠나지 못했다). 노선을 차로가 이어지는 길(B1은 `R51`에서, B4는 `R54a`로)로 골라야 한다.
- 시험용 버스의 도착 보장 정지(`forced`)는 지웠다. 창 끝 앞 달리는 차로에서 멈추는 대신 SUMO 차선 변경에 넘기고, 정류장 차로에 못 가면 그 정류장을 건너뛴다. 좌회전 차로에 못 가면 정지선에서 기다릴 수 있다(차로 끝 대기).
- S1은 정류장이 차로 정차형(정차하면 그 차로가 막힘)이라는 확정(사용자)에 따라 구현했다. 합정역 지도의 정류장은 모두 차로 위 `busStop`이라 이 가정과 맞다. 정류장 앞 대기열은 한 대(바로 뒤 한 대)만 다룬다. 확장 여부는 정해지지 않았다.

S5 대상은 이제 도로망에서 자동으로 찾는다(위 3.4.0 시점에는 `G3`, `G12`뿐이었다). 배경 차량은 무작위 간격으로 들어온다(`flow_arrivals`).
