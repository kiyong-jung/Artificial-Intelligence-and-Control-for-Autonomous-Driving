# 주변 교통(Traffic)

자율주행버스 주변의 다른 차량과 보행자가 버스를 마주했을 때 어떻게 반응하는지를 SUMO에서 구현하고, 설정한 대로 나오는지 숫자로 확인한다. 버스 자체의 주행 정책은 범위 밖이다. 버스는 외부에서 들어오는 차량으로 취급하고 `bus_hook(traci, t)`로만 붙는다.

검증 수치와 한계 전부는 [VERIFICATION.md](VERIFICATION.md)에 있다. 이 문서는 구조, 사용법, 이슈를 적는다.

### 주행 모델과 양보 성격

배경 차량의 주행 모델은 `env/road_config.py`가 정한다(Krauss 35%, IDM 30%, EIDM 20%, ACC 15%). 양보 성격은 그 위에 독립으로 붙는다.

- `YieldManager(type_mix={"yielder": .5, "nonyielder": .5}, mix_vtype_prefixes=("car_",))`를 주면, 이름이 `car_`로 시작하는 차량이 투입될 때 성격을 뽑아 받는다. 주행 모델은 바뀌지 않는다.
- 차량마다 `driver.type`, `driver.pYield`, `driver.pClose`, `driver.aggressiveness`, `driver.delay`, `driver.newTau`가 차량 파라미터로 기록된다.
- **공격성 값**(`driver.aggressiveness`, 0~1)은 차량마다 투입 시 한 번 뽑고(양보형 0.05~0.30, 비양보형 0.70~0.95의 **두 집단**, 사용자 확정), 주행 모델과는 독립이다. S1·S5는 이 값을 확률로 바꿔 판정에 쓴다(`common.AggressionMap`, 값은 자리표시). A1은 확률을 쓰지 않고 **투입 때 확정한 행동**(`driver.action`)을 쓴다.
  - A1 양보형 = 감속, 비양보형 = 유지 또는 가속(`driver.pClose` 0.3로 투입 때 한 번 뽑음)
  - S1 추월 확률 `0.2 + 0.7a`
  - S5 끼어들기 확률 `0.2 + 0.8a` (끼어들기 vType의 구간이 곧 공격성이다)
- 인자를 주지 않으면 vType 이름이 `yielder`, `nonyielder`로 시작하는 시험 차량만 대상이다.
- 양보형도 SUMO 내장 협조 차선 변경을 끈다(`lcCooperative=-1`, `lcCooperativeSpeed=0`). 켜 두면 양보 판정과 무관하게 SUMO가 길을 비켜서 양보율이 100%가 된다.
- `type_mix`를 켜면 `car_*` 차량 전체에 위 설정이 적용되어, 투입 이후 배경 차량의 차로 변경이 SUMO 기본과 달라진다.

### 합정역 연결 (`hapjeong.py`)

`HapjeongTraffic`은 도로를 공식 경로로만 만든다. `maps/hapjeong`을 `configure_map`이 읽고, `road_builder.build`가 실행 폴더를 만든다. `maps/`와 도로망 파일은 건드리지 않는다. 실행 폴더에 다음을 더한다.

| 이름 | 내용 |
|---|---|
| A1 | 배경 차량 `car_*`에 양보 성격을 투입 시 붙인다 |
| S1 | `run(stop_bypass=True)`(기본). 버스가 정류장에 서면 바로 뒤 차량이 기다리거나 추월한다 |
| S5 | 버스 경로(`bus_loop`)에 합류하는 골목을 도로망에서 **자동 탐지**(`traffic/alleys.py`)해, 그 골목으로 나오는 흐름을 끼어들기형 vType으로 바꾼다. 합류점은 8곳(`X_dongmak3`, `X_dongmak6`, `X_wausan11`, `J74`, `X_jandari7`, `X_jandari2`, `X_jandari3`, `J48`)이고 흐름 62개다. 골목에서 출발하는 흐름과 고리 골목을 `via`로 지나 합류하는 흐름이 모두 대상이다. 고리를 나와 반대 방향(`-R71.55`)으로 가는 흐름은 버스와 만나지 않아 대상이 아니다 |
| S6 | 와우산로 횡단보도를 건너는 보행자를 P1/P2로 나누고, 신호 없는 횡단보도(`S6_wausanro`) 앞 보행자의 건너기 판정은 `PedDefianceManager`가 한다(`run(ped_defiance=True)`, 기본) |
| S4 | `HapjeongTraffic(stopped=[StoppedSpec(...)])` 또는 `taxi_depart`(예전 방식). 정차 차량은 택시·버스·일반 차량이고 위치·시각·정차 시간·확률을 받는다. 스크립트에서는 `--stopped`로 켠다 |

`start()`가 배경 교통을 180초 흘리고, `run()`이 공통 실행 루프를 돌린다. 버스는 만들지 않는다. 버스 제어 쪽이 `bus_hook`으로 넣고 몬다. `run(triggers="scenario")`는 A1이 버스의 의사를 읽는 구간을 S2(좌회전 직전), S3(정류장 접근), S4(정차 차량 앞)로 한정한다. 기본(`None`)은 방향지시등만 본다.

## 실행

```bash
python scripts/run_hapjeong_scenario.py                         # sumo-gui가 열리고 버스를 따라간다
python scripts/run_hapjeong_scenario.py --nogui --seconds 900   # 화면 없이 요약만
pytest tests                                                    # 62개, 2~4분(컴퓨터 부하에 따라)
python scripts/verify_additional.py                             # 추가 행동 검증 전체(r1 s1 scope s4 s5 ped det hap). 인자로 골라서 돌린다
```

정차 차량(S4)을 스크립트에서 켜는 예. 쉼표로 이은 `key=value`이고 `--stopped`는 여러 번 줄 수 있다.

```bash
# 합정역7번출구 정류장 14m 앞에 택시, warmup 60초 뒤 투입, 40초 정차
python scripts/run_hapjeong_scenario.py --nogui --stopped kind=taxi,stop=합정역7번출구,depart=60,duration=40
# 도로·차로·위치를 직접: 버스 한 대, 발생 확률 0.5
python scripts/run_hapjeong_scenario.py --nogui --stopped kind=bus,edge=R112,lane=1,pos=60,depart=100,duration=40,prob=0.5
```

`kind`는 `taxi`, `bus`, `car`(일반 승용차)이다. `depart`는 warmup이 끝난 시점부터 센 초다. `--triggers scenario`, `--no-stop-bypass`, `--no-ped-defiance`도 있다.

시나리오 화면에서 보이는 것:

- 빨간 버스가 정류장 6곳에 8초씩 서며 `bus_loop`를 돈다(한 바퀴 약 417초). 차로 변경이 필요하면 방향지시등을 3초 켠 뒤 요청한다. 주행 정책이 아니라 규칙이다.
- 주변 차량 색은 주행 모델이다. 노랑 Krauss, 청록 IDM, 주황 EIDM, 자홍 ACC, 회색 끼어들기 차량.
- 버스가 차로 변경 의사를 보이면 뒤차에 고리가 생긴다. 초록은 이번 상호작용에서 양보, 빨강은 비양보로 판정한 것이다. 고리는 끝난 뒤 4초 더 남는다. 같은 내용을 터미널에도 한 줄씩 적는다.
- 차량은 투입 때 양보형 또는 비양보형으로 정해지고, 양보형은 버스를 마주치면 항상 양보(감속), 비양보형은 양보하지 않는다(유지 또는 가속). 같은 차량이 여러 번 마주쳐도 행동이 같다. `driver.pYield`는 공격성 값(1-p)의 원천이고 A1 행동을 정하지 않는다.
- 차량을 더블클릭하면 파라미터에서 `driver.type`, `driver.pYield`를 볼 수 있다.

교통이 한산해 상호작용이 드물어서 두 가지 장치를 넣었다. 둘 다 확인용이고 실제 교통이 아니다.

- 시험 차로 변경(`--probe`, 기본 10초): 옮겨 갈 차로 뒤 40m 안에 차가 있으면 일부러 그쪽으로 차로를 바꾼다. 0이면 끈다.
- 동행 차량(`comp1`처럼 표시): 뒤에 차가 없으면 30m 뒤에 배경 차량 한 대를 넣는다. `--no-companion`으로 끈다.

그 밖의 옵션: `--seed`, `--scenario quiet|baseline|busy`, `--delay`(클수록 느림), `--zoom`, `--no-track`, `--no-stops`, `--no-overtake`, `--seconds`, `--inject`(시나리오 주입기), `--no-cruise`(순항 규칙 끔), `--lane-buses`·`--taxis`(배경 버스·택시 대수).

**시험용 버스의 순항 규칙(`LoopBus`)**: 정류장을 떠나면 가로변 차로(1번)에서 한 칸 왼쪽으로 옮겨 달리고, 다음 정류장 150 m 앞에서 오른쪽으로 돌아온다. 이 노선은 버스가 정류장 차로에 계속 있어 오른쪽 차선변경(S3)이 필요 없었기 때문이다(예전 S3 "시도"는 모두 한 바퀴를 마치기 0.4초 전의 거짓 시도였다). 주입기가 켜져 있으면 버스는 방향지시등을 켠 채 목표 차로 후행차가 40 m 안에 올 때까지(최대 12초) 기다렸다가 차선변경을 요청한다.

**측정**: `scripts/measure_s1_s6.py <수요> <seed> [꼬리표]`가 시험용 버스 3바퀴 동안 S1~S6 횟수, 횡단보도 앞 차량 대기, 충돌·순간이동, 버스가 정류장 밖에서 15초 넘게 선 곳을 센다. 꼬리표: `inject`(주입기), `old`(보행자 수정 전 설정), `hiped`(횡단보도 보행자 4배), `noror`(우회전 끔), `nointer`(밀도 분산 끔), `noahead`(정류장 앞 정차 끔). 한 번에 6~25분이 걸린다(3개를 동시에 돌리면 더 걸린다).

알고리즘별 상세 검증은 `scripts/verify_a1.py`, `verify_a2.py`, `verify_a3.py`, `verify_hapjeong.py`이고 결과는 `results/traffic_verification/`에 쓴다.

## 이슈와 한계

**아직 이어지지 않은 것**

- `traffic/`은 학습 환경 `SumoHighwayEnv`에 연결되어 있지 않다. 학습은 팔달문에서만 돌고, 합정역은 0번 차로가 인도라 차로 번호 관측이 틀려 막혀 있다. 합정역 주변 교통은 시나리오 스크립트와 검증 스크립트에서만 돈다.
- 버스 정책 코드가 없다. `bus_hook`과 시험용 규칙 버스로만 확인했다. 버스 쪽이 지킬 것은 두 가지다.
  - 차로 변경 전에 방향지시등을 켠다. A1의 진입 의사 판정 조건이다(방향지시등, 출구 거리, 직전 2초 전진).
  - `laneChangeMode`를 1109나 0으로 쓰지 않는다. 뒤차가 양보하든 말든 버스가 밀고 들어가 양보 검증이 성립하지 않는다. 1621, 512는 정상이다.

**우회전과 보행자**

- 우회전은 겹치는 직진·좌회전이 녹색이 아니고 횡단보도 보행자 신호가 적색일 때만 열려서, 원래 막힌 시간의 약 16~67%만 열린다(J74 67%, J42 39%, J96 41%, J82 43%, J83 19%, J52 군 16%). 런타임에 링크 상태를 바꾸는 보호 장치(`setLinkState`)는 합정역에서 교차로를 막아(순간이동 30건, 버스 R73 정지) 쓰지 않는다.
- J96의 우회전 링크(`-R127→R124`)에서 차량-보행자 충돌이 측정 중 간혹 나왔다. 그 링크는 원래 프로그램에서도 37% 동안 녹색(`g`)이라 우회전을 열기 전부터 있던 위험일 수 있으며 확인하지 못했다.

**시나리오 발생이 보장되지 않는다**

- 합정역 교통이 한산해서 자연 교통에서는 버스가 뒤차와 상호작용하는 일이 한 바퀴에 한두 번이다.
- S5(골목 흐름이 시간당 약 23대)와 S6는 시나리오 스크립트에서 발생을 확인하지 못했다. S4는 `--stopped`로 켜야 일어난다(기본은 꺼짐).
- S1은 정류장이 차로 정차형(정차하면 그 차로가 막힘)이라는 확정(사용자)에 따라 구현했다. 합정역 지도의 정류장은 모두 차로 위 `busStop`이라 이 가정과 맞다. 정류장 앞 대기열은 한 대(바로 뒤 한 대)만 다룬다. 확장 여부는 정해지지 않았다.
- S1의 기다림은 후행차가 정차한 버스에서 200m 안에 들어올 때부터 차로를 고정한다(`StopBypassManager.follower_range`). SUMO 기본 모델은 그보다 먼 거리(IDM은 100m 밖)에서 이미 옆 차로로 빠지기 때문이다. 이 범위가 짧으면 기다림 판정이 새어 추월이 된다.
- S2(정류장 직후 좌회전 연속 차로 변경)는 시나리오에서 필요한 차로 변경이 있었는지 확인하지 못했다.

**도로**

- 도로망이 3.6.0이 됐다. 어울마당로 북행이 독막로에서 시작한다. 원본 토막 `R122`와 새 골목 `G31`(`J94` → `Y5`)이 생겼고, 어울마당로 골목 차는 `G19` 대신 `G31`에서 출발한다. 독막로·어울마당로 교차로(`cluster_J52_J56_J58`)의 신호는 `signals.add.xml`에 직접 적었다(주기 90초 그대로). 버스 경로는 1,949m가 됐다.
- 도로망이 3.5.0이 됐다. 막다른 길이던 독막로6길 `G12`를 독막로4길 `G30`, 성지1길 `G11`과 이어, 성산중학교 정류장 앞 `X_dongmak4`에서 들어가 정류장 끝 `X_dongmak6`으로 나오는 고리로 만들었다. `G12`에서 출발하는 흐름은 없고, 독막로를 지나는 흐름 일부가 `via="G30 G11 G12"`로 고리를 지난다(`map.json`의 `flows`에 `via`가 생겼다). `_retype_alley_flows`(지금은 골목 자동 탐지)는 이 `via` 흐름 가운데 버스 경로로 합류하는 것을 `cutin`으로 바꾼다. 독막로가 한 번 더 나뉘어 `R71.135`는 64m로 짧아졌고, 성산중학교 정류장은 `R71.206`에 있다.
- 도로망이 3.4.0이 됐다. 골목은 모두 나오는 방향의 일방통행이고, 독막로 남쪽 골목망과 `G1`·`G2`·`G5`~`G7`·`G9`~`G11`·`G13`~`G15`는 없어졌다. `G16`으로 나오는 차는 `G4`에서, `G18`로 나오는 차는 `G17`에서 출발한다. 독막로 `R111b`는 차도 3차로다(2번·3번 차로가 좌회전). 신호는 `J82`, `J42`, `J106`, `J48`이 바뀌었다([maps/hapjeong/README.md](../maps/hapjeong/README.md)의 3.4.0 절). 골목이 버스 경로로 나오는 도로는 `G3`·`G12`(독막로), `G24`(와우산로, 극동방송 앞), `G19`(잔다리로 `J74`), `G16`·`G23`·`G18`(잔다리로), `G22`(잔다리로 `J48`, 좌회전 대기 구간 앞)다. S5 대상은 이제 도로망에서 자동으로 찾는다(위 3.4.0 시점에는 `G3`, `G12`뿐이었다). 배경 차량은 무작위 간격으로 들어온다(`flow_arrivals`).
- 도로망이 3.2.0으로 바뀌었다(북서쪽을 잘라내고 잔다리로로 나오는 지름길 두 개를 더함, [maps/hapjeong/README.md](../maps/hapjeong/README.md)). 위 검증 수치는 2.0.0 도로 기준이므로 다시 돌려야 한다. 3.2.0에서는 `pytest tests` 통과만 확인했다. `R43`은 맨 왼쪽 차로가 버스 전용이다. 잔다리로 `-R96`은 합류점 두 곳에서 나뉘어 `-R96`, `-R96.64`, `-R96.201`이 됐다. 신호 없는 횡단보도에는 보행자 `s6ped*`가 시간당 60명 건넌다.
- 이 코드가 기대는 도로 ID. 바꾸면 알려야 한다.
  - 합류 골목은 더 이상 id로 적지 않는다. `bus_loop` 경로와 도로망의 제한속도(30km/h 이하 = 골목), 연결 상태로 찾는다. 합류점 8곳이 줄거나 늘면 `tests/test_hapjeong_integration.py`가 알려 준다
  - 횡단보도 `S6_wausanro`와 와우산로 `R112`, `-R112`
  - 4차로 구간 `R43`, `R71`, `R71.135`
  - 택시용 `R69`와 주차 차로 `R69_1`
  - `bus_loop` 경로와 정류장 6곳
- S6 횡단보도는 보행자 유형이 의미를 갖도록 비우선으로 바꿨다. 한국 법규(운전자 일시정지 의무)와 다르다.

**값**

- 양보 확률, 반응 지연 분포, 공격성 값→확률 변환(`AggressionMap`), 끼어들기 분포는 임의의 초깃값이다. 끼어들기의 SUMO 기본 방식(`default_bins`)은 설정 확률이 곧 진입 확률이 아니어서(설정 0.05에서 실측 0.13, `jmIgnoreFoeProb`를 접근 중 여러 번 뽑기 때문) 합정역에서는 무시 확률을 0 또는 1로만 두고 그 비율을 확률로 맞추는 `cutin_bins_once()`를 기본으로 쓴다.
- A3 보강(`PedDefianceManager`)의 기본 건너기 확률 0.4, 통과 시간·대기 시간·그룹·폭·차량 크기·걷는 중 계수 곡선, 나이 계수, 스마트폰 주의 분산 확률은 모두 PedSUMO(독일 자료)의 값을 옮긴 초깃값이다. **한국 현장 자료로 바꿔야 한다.**
- 승객 가중 지연의 탑승 인원(승용 1.3, 택시 1.5, 버스 20)은 근거 없는 가정값이다.
- 배경 차량의 추종 모델 파라미터도 현장 실측값이 아니다.
